# The Garage

A multi-agent system that fixes real bugs in real codebases (SWE-bench Lite),
where every patch must clear **two gates** — a correctness gate (tests) and a
simplicity gate (anti-over-engineering review) — before it ships. Every state
change is emitted to an append-only event log, which drives a live pixel-art
visualization and a time-travel replay debugger.

The differentiator is not the pixel art. It is that the system **grades its own
output and reports a success rate** — which ChatDev, MetaGPT, AI Town and
Munder Difflin do not.

## How it works

```
issue → orchestrator → scout builds context pack
                            ↓
                     builder writes patch
                            ↓
                     tester applies patch, runs tests (Docker)
                      ↓                ↓
                    fail             pass
                      ↓                ↓
          back to builder        reviewer checks simplicity
          with failure log        ↓                ↓
          (max 3 retries)      reject            pass
                                  ↓                ↓
                        back to builder          SHIP
                        (max 1 retry)
```

Two gates measuring **opposite pressures** — correctness wants more code,
simplicity wants less. Separate retry caps guarantee termination: the builder
runs at most `1 + 3 + 1 = 5` times per task.

Gate on/off is edge rewiring at graph build time, not a branch inside a node —
the OFF arm is structurally incapable of invoking the gate, which is what makes
the A/B honest.

## Quickstart

Requires Python 3.12, [uv](https://docs.astral.sh/uv/), Docker (running), and
ripgrep.

```bash
git clone https://github.com/DEKU-12/garage && cd garage
uv sync
```

Verify the grading harness before anything else — it grades a task's own gold
patch (must pass) and an empty patch (must fail). No API key, no model call, $0:

```bash
uv run python -m engine.eval.verify_harness django__django-11099
```

> **Apple Silicon:** SWE-bench publishes `x86_64` images only, so Docker's pull
> fails with `no matching manifest for linux/arm64`. The grader handles this by
> pre-pulling with `--platform linux/amd64` and letting the container run under
> emulation — nothing to configure, but the first pull per repo is a few GB.

Not built yet (week 1 in progress):

```bash
cp .env.example .env   # add your GROQ_API_KEY
uv run garage run-one --task django__django-11099
```
